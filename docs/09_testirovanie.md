# 09. Тестирование проекта

## Запуск тестов

```bash
pip install -r requirements-dev.txt
pytest                 # все тесты
pytest -v              # подробный вывод по каждому тесту
pytest tests/test_bot_flow.py          # только сценарии бота
pytest -k holidays     # только тесты, связанные с праздниками
```

Тесты **не требуют** интернета, Telegram и PostgreSQL:

* внешние API подменяются фейками (`tests/fakes.py`);
* HTTP-слой подменяется `FakeSession` (ответы заранее подготовлены);
* база данных — временный SQLite-файл (структура таблиц идентична PostgreSQL);
* Telegram — `FakeGateway`, который записывает «отправленные» сообщения.

## Что именно проверяется по слоям

### Доменный слой (бизнес-правила)

* праздники берутся только из диапазона [сегодня; сегодня + 7 дней], сортируются по дате,
  показываются не более 5;
* на стыке годов запрашиваются два года, повторы исключаются;
* из ближайших городов исключаются город пользователя и дубликаты, берётся первые 5;
* заметка длиннее 1000 символов не сохраняется, пустая заметка отклоняется;
* название города обрезается до 50 символов (ограничение поля `name`);
* ошибки внешних сервисов преобразуются в доменные исключения с готовым текстом.

### Слой инфраструктуры

* структура таблицы: `id` — первичный ключ, `note` — nullable, `name varchar(50)`,
  `note varchar(1000)`;
* история сортируется от новых к старым, пагинация считает страницы и не выходит за границы;
* поездка чужого пользователя недоступна ни на чтение, ни на изменение;
* клиенты API отправляют правильные параметры и заголовки (`X-Api-Key`, `username`, `radius`);
* ответы API разбираются корректно, в том числе при нестандартных форматах даты;
* таймаут, ошибка соединения, HTTP 4xx/5xx и не-JSON приводят к `ExternalServiceError`.

### Слой представления

* тексты сообщений совпадают с техническим заданием (посимвольно для ключевых строк);
* клавиатуры содержат нужные кнопки в нужном порядке и с правильными callback-данными;
* на первой странице истории нет кнопки «Назад», на последней — «Вперёд»;
* состояние пользователя переходит между экранами и изолировано по пользователям;
* сквозные сценарии: `/start` → меню → каждый из трёх разделов → возврат;
* непредвиденная ошибка (например, «упала» база) не выходит наружу: пользователь видит
  «Произошла ошибка. Попробуйте ещё раз позже.», а бот продолжает работу.

## Пример сквозного теста

```python
def test_select_city_saves_trip_and_shows_info(flow: Flow):
    flow.command_start()
    flow.send_text("Города куда съездить")
    flow.send_text("Москва")

    text = flow.press("city:1")

    # поездка сохранена в базе данных
    assert flow.repository.count_by_user(USER_ID) == 1
    assert flow.repository.find_by_user(USER_ID, 10, 0)[0].name == "Тула"

    # показана информация о городе из Википедии
    assert flow.gateway.photos, "ожидалось сообщение с фотографией города"
    assert "Город: Тула" in text
    assert "Расстояние от города Москва: 172 км" in text
```
