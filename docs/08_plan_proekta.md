# 08. План проекта TravelHunter

Проект выполняется по схеме: **занятие в среду** — общий шаг по проекту,
**занятие в пятницу** — разбор личного проекта и проблем. Ниже — план на 4 недели
с артефактами, задачами и критериями готовности.

## Этап 0. Подготовка (до начала работы)

| Задача | Результат |
|--------|-----------|
| Установить Python 3.10+, Git, VS Code | окружение готово |
| Зарегистрироваться на GitHub | аккаунт для пуша проекта |
| Создать репозиторий, клонировать его локально | пустой репозиторий + локальная папка |
| Установить расширения VS Code (Git Graph) | удобная работа с ветками |
| Прочитать методички «работа в соло» и «работа в команде» | понятен процесс |

## Этап 2. Каркас проекта и база данных (неделя 2)

| Задача | Результат |

| Создать структуру пакетов (три слоя) | `travelhunter/{presentation,domain,infrastructure}` |

**Критерий готовности:** `python -m scripts.init_db` создаёт таблицу;
тесты репозитория зелёные; коммит отправлен в GitHub.

## Этап 3. Внешние API и бизнес-логика (неделя 3)

| Задача | Результат |
|--------|-----------|
| Общий HTTP-клиент с обработкой сетевых ошибок | `JsonHttpClient` |
| Клиент Ninjas Holidays API (праздники) | `NinjasHolidaysClient` |
| Клиент GeoNames (поиск города, ближайшие города) | `GeoNamesClient` |
| Клиент Wikipedia (описание + фото города) | `WikipediaClient` |
| Сервисы `HolidayService`, `CityService`, `TripService` | бизнес-правила: 7 дней / 500 км / 5 элементов / 1000 символов |
| Доменные исключения с текстами для пользователя | `domain/exceptions.py` |
| Тесты сервисов и клиентов на фейках | `tests/test_*_service.py`, `tests/test_api_clients.py` |

**Критерий готовности:** сервисы работают без Telegram и без реальной сети (тесты),
все ошибки преобразуются в доменные исключения.

## Работа с Git

| Правило | Практика в проекте |
|---------|--------------------|
| Один этап = несколько небольших коммитов | коммит после каждого экрана/сервиса |
| Понятные сообщения коммитов | `feat: экран 3 праздники (Ninjas API)`, `fix: пагинация истории поездок` |
| Секреты не попадают в Git | `.env` в `.gitignore`, в репозитории только `.env.example` |
| Работа в ветке | `git switch -c feature/screen-3-holidays` → merge в `main` через PR |
| История видна в Git Graph | расширение VS Code Git Graph |

Пример последовательности коммитов этого проекта:

```
chore: каркас проекта, требования, .env.example
feat(domain): сущности, исключения и интерфейсы доменного слоя
feat(infra): SQLAlchemy-модель visited_cities и репозиторий поездок
feat(infra): клиенты Ninjas, GeoNames и Wikipedia API
feat(domain): сервисы праздников, городов и поездок
feat(presentation): тексты, клавиатуры, состояния и шлюз Telegram
feat(presentation): экраны 1–9 и обработчики событий
feat: композиционный корень приложения и точка входа
test: 198 тестов сервисов, клиентов, репозитория и сценариев бота
docs: README и артефакты проекта (план, диаграммы, описание экранов)
```

## Риски проекта и меры

| Риск | Вероятность | Мера |
|------|-------------|------|
| Лимиты GeoNames (бесплатный аккаунт) | высокая | кэширование не требуется для MVP; при ошибке показываем понятное сообщение и предлагаем повторить позже |
| Ninjas API не вернёт праздники на нужный период | средняя | запрос двух годов на стыке лет; сообщение «праздников не найдено» |
| В Википедии нет статьи о малом городе | средняя | показываем информацию без описания/фото, поездка всё равно сохраняется |
| Потеря состояния при перезапуске бота | высокая (память) | дружелюбное сообщение и возврат в главное меню; при необходимости состояние можно перенести в БД |
| Telegram API недоступен | низкая | ошибки шлюза логируются, бот не падает |

## Дальнейшее развитие (не входит в MVP)

* кэширование ответов внешних API в базе данных;
* поиск по названию праздника и фильтры истории поездок;
* экспорт истории поездок в файл;
* хранение состояния пользователя в PostgreSQL вместо памяти;
* деплой бота на сервер и запуск через systemd/Docker;
* логирование в файл и метрики использования экранов.
