# 08. План проекта GameHunter

Проект рассчитан на 4 недели работы одного разработчика. Каждый этап заканчивается
работающим кодом и коммитом в Git: так в любой момент можно показать прогресс.

> Проект начинался как TravelHunter (подбор путешествий на выходные). После
> согласования с заказчиком предметная область была изменена на поиск видеоигр,
> поэтому план ниже описывает фактические этапы разработки GameHunter: каркас и
> инфраструктурные решения (трёхслойная архитектура, обработка ошибок, тесты,
> документация) были перенесены из первой версии, доменная часть написана заново.

## Этап 3. Внешние API и бизнес-логика (неделя 3)

**Цель:** доменные сервисы работают с подставными провайдерами и с реальными API.

- [x] `JsonHttpClient`: таймаут, коды ответа, `allow_404`, JSON, преобразование
      ошибок в `ExternalServiceError`
- [x] `RawgClient`: жанры, платформы (с запасным перечнем), поиск игр, карточка
      игры, франшизы, игры франшизы
- [x] `IpLocationClient`: ipapi.co и ipwho.is (оба формата ответа), `Region`
- [x] `AgePolicy`: ESRB и PEGI → минимальный возраст, проверка «подходит ли игра»
- [x] `GameService`: справочники с кэшем, построение запроса, слияние с анкетой,
      исключение сыгранных игр, возрастной фильтр, карточки, франшизы
- [x] `ProfileService`: анкета, валидация возраста, извлечение и проверка IP,
      определение региона
- [x] `LibraryService`: сыгранные игры, отзывы (до 1000 символов), избранное, пагинация

**Критерий готовности:** юнит-тесты сервисов проходят на `FakeGamesProvider`,
`FakeIpProvider` и SQLite; ручной запрос к RAWG возвращает ожидаемые игры.

## Работа с Git

| Правило | Как применяется в проекте |
|---------|---------------------------|
| Одна задача — один коммит | каркас, домен, инфраструктура, экраны, тесты, документация — отдельные коммиты |
| Понятные сообщения в стиле Conventional Commits | `feat(domain): …`, `test: …`, `docs: …`, `chore: …` |
| Секреты не попадают в репозиторий | `.env` в `.gitignore`, в Git только `.env.example` |
| Рабочая ветка + pull request | работа в ветке `arena/01a0bfe2-geminfo`, изменения оформлены PR в `main` |
| Тесты перед коммитом | `make lint && make test` |

Пример последовательности коммитов проекта:

```
chore: каркас проекта — зависимости, шаблон настроек, Makefile, docker-compose
feat(domain): сущности, возрастные рейтинги, исключения и интерфейсы
feat(infra): SQLAlchemy-модели анкеты, сыгранных игр и избранного + репозитории
feat(infra): HTTP-клиент, клиенты RAWG и геолокации по IP
feat(domain): сервисы подбора игр, анкеты и библиотеки
feat(presentation): тексты, клавиатуры, состояние пользователя и шлюз Telegram
feat(presentation): 17 экранов и обработчики событий с перехватом ошибок
feat: настройки из окружения, композиционный корень и точка запуска
test: 1409 тестов домена, инфраструктуры, экранов и сквозных сценариев
docs: документация, диаграммы DrawIO, SVG-мокапы и README
```

## Риски проекта и меры

| Риск | Вероятность | Последствие | Мера |
|------|-------------|-------------|------|
| Лимиты RAWG (20 000 запросов/месяц, 20 записей на страницу) | средняя | подборка перестаёт работать | кэш справочников и карточек, `DETAILS_FETCH_LIMIT` ограничивает догрузку карточек, `page_size` ≤ 20 |
| Возрастного рейтинга нет в списке игр | высокая (подтвердилось) | нельзя фильтровать по возрасту одним запросом | догрузка карточек для части игр + фильтр в `GameService`; игры без рейтинга показываются |
| Лимит ipapi.co (≈1000 запросов/сутки) | низкая | регион не определяется | результат сохраняется в анкете и повторно не запрашивается; запасной сервис ipwho.is через `IP_LOCATION_BASE_URL` |
| Telegram не передаёт IP пользователя | высокая (подтвердилось) | нельзя определить регион автоматически | пользователь присылает IP вручную; в интерфейсе и документации это объяснено |
| Пользователь нажимает кнопку устаревшего сообщения | средняя | ошибка «нет данных» | `state_lost`: понятное сообщение и возврат в главное меню |
| Ошибка внешнего сервиса во время диалога | высокая | падение бота | все вызовы обёрнуты: доменные исключения + `safe_handler` |
| Разрастание состояния в памяти | низкая | утечка памяти при долгой работе | контекст хранится по одному на пользователя и перезаписывается; при необходимости легко заменяется на Redis (интерфейс `StateStorage` изолирован) |

## Дальнейшее развитие (не входит в MVP)

1. **Рекомендации по похожим играм**: `GET /games/{id}/game-series` и
   `GET /games?dates=…&genres=…` — «если понравилась эта игра, попробуйте…».
2. **Магазины и цены региона**: показывать магазины из карточки с учётом валюты
   региона пользователя.
3. **Поиск по названию игры**: отдельный экран с `GET /games?search=…`.
4. **Статистика пользователя**: сколько игр пройдено, средний рейтинг, любимые
   жанры (агрегаты по `played_games`).
5. **Сохранение состояния в Redis**: чтобы перезапуск бота не сбрасывал диалог.
6. **Вебхук вместо long polling**: для размещения на сервере с постоянным адресом.
7. **Миграции Alembic**: изменение схемы без пересоздания таблиц.
8. **Кнопка «Поделиться подборкой»**: отправка списка игр другу.
