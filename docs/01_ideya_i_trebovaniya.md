# 01. Идея проекта и технологические требования

## Идея проекта

Telegram-бот **GameHunter** помогает пользователю найти видеоигру по его интересам.

* Пользователь выбирает жанры (интересы), которые ему нравятся, и бот показывает
  подборку игр из каталога RAWG: название, год выхода, рейтинг, жанры, платформы.
* Пользователь может искать игры по **франшизе** — интеллектуальной собственности
  (IP): Marvel, Star Wars, Warcraft, The Witcher и другим.
* Пользователь заполняет **анкету**: возраст, интересы, платформы и регион.
  Регион определяется по IP-адресу (город, страна, часовой пояс, валюта).
* Бот спрашивает и запоминает, **во что пользователь уже играл**: такие игры
  исключаются из подборок, а по ним можно оставить отзыв (до 1000 символов).
* Понравившиеся игры можно сохранить в **избранное**.
* Все данные пользователя хранятся в базе данных PostgreSQL.

## Основные возможности

1. подбор игр по выбранным жанрам (интересам) с пагинацией;
2. подбор игр с учётом анкеты: возраст, интересы, платформы;
3. поиск игр по франшизе (IP) — ввод названия, выбор франшизы, список её игр;
4. карточка игры: описание, разработчик, издатель, магазины, возрастной рейтинг;
5. отметка «Уже играл» с автоматическим исключением игры из следующих подборок;
6. список «Во что я играл» с пагинацией, отзывом и удалением записи;
7. избранное: добавление, удаление, просмотр;
8. анкета пользователя: возраст, интересы, платформы, регион по IP;
9. обработка ошибок внешних сервисов и базы данных без падения бота.

## Возрастной фильтр

Возрастной рейтинг игры берётся из каталога (ESRB / PEGI) и переводится в
минимальный возраст по таблице из `gamehunter/domain/age_ratings.py`:

| Рейтинг | Минимальный возраст |
|---------|---------------------|
| EC (ESRB) | 3 |
| E (ESRB) | 6 |
| E10+ (ESRB) | 10 |
| T (ESRB) | 13 |
| M (ESRB) | 17 |
| AO (ESRB) | 18 |
| PEGI 3 / 7 / 12 / 16 / 18 | 3 / 7 / 12 / 16 / 18 |

Если в анкете указан возраст, бот показывает только те игры, чей минимальный
возраст не больше возраста пользователя. Игры без возрастного рейтинга
показываются всегда (отсутствие данных не считается ограничением).

## Технологические требования

| Требование | Как реализовано в проекте |
|------------|---------------------------|
| Язык программирования Python | Python 3.10+ (разработка велась на 3.11) |
| `telebot` для взаимодействия с Telegram | `gamehunter/presentation/` — экраны, клавиатуры, обработчики, шлюз |
| `requests` для HTTP-запросов к внешним API | `gamehunter/infrastructure/api/http_client.py` и клиенты сервисов |
| `psycopg2` для взаимодействия с PostgreSQL | драйвер указан в `DATABASE_URL=postgresql+psycopg2://…` |
| `sqlalchemy` для работы с базой данных через ORM | `gamehunter/infrastructure/db/` — модели 2.0-стиля и репозитории |
| API-ключ RAWG не хранится в коде и не публикуется в Git | ключ читается из `RAWG_API_KEY` (файл `.env` в `.gitignore`) |
| Код в ООП-стиле | классы сервисов, клиентов, репозиториев, экранов; наследование и интерфейсы (ABC) |
| Трёхслойная архитектура | `presentation` → `domain` ← `infrastructure` (см. [05_arhitektura.md](05_arhitektura.md)) |
| Взаимодействие с БД через SQLAlchemy | только через `SqlProfileRepository` и `SqlLibraryRepository`; сервисы работают с интерфейсами `ProfileRepository` и `LibraryRepository` |
| Обработка ошибок Telegram | декоратор `safe_handler` в `handlers.py`, ошибки шлюза логируются в `gateway.py` |
| Обработка ошибок базы данных | `SQLAlchemyError` → `DatabaseError` → понятное сообщение пользователю |
| Обработка ошибок внешних сервисов | `ExternalServiceError` и его наследники, дружелюбные сообщения |
| Ошибка не приводит к аварийному завершению бота | все исключения перехватываются; бот продолжает принимать апдейты |

## Безопасность секретов

* `.env` добавлен в `.gitignore` — в репозиторий попадает только `.env.example`;
* ключи читаются в одном месте — `gamehunter/config.py` (класс `Settings`);
* в исходном коде нет ни одного ключа: поиск по `api_key =` покажет только
  чтение значения из настроек;
* строка подключения к базе логируется без пароля (`Database.safe_url`);
* IP-адрес пользователя хранится в базе как часть анкеты и не передаётся
  в логи целиком (в логах — только факт обращения к сервису геолокации).

## Ограничение Telegram Bot API (важно для функции «регион по IP»)

Telegram Bot API **не передаёт боту IP-адрес пользователя**: в апдейте есть
только `id`, `username`, `first_name` и другие поля профиля. Поэтому регион
определяется так:

1. бот просит пользователя прислать свой **публичный** IP-адрес сообщением
   (его можно посмотреть, например, на сайте 2ip.ru);
2. бот проверяет адрес (формат IPv4/IPv6, не локальный ли он);
3. бот отправляет адрес в сервис геолокации и сохраняет результат в анкету.

Альтернатива — пользователь вручную вводит город; в проекте реализован
первый вариант, так как он даёт часовой пояс и валюту автоматически.
