# 01. Идея проекта и технологические требования

## Идея проекта

Telegram-бот **TravelHunter** помогает пользователю выбрать город для небольшого
путешествия выходного дня.

* Пользователь может посмотреть список российских праздников на ближайшие 7 дней.
* Пользователь может указать город, в котором он сейчас находится. После этого бот
  предлагает ближайшие города, расположенные в радиусе 500 км, куда можно съездить.
* Пользователь может выбрать один из предложенных городов. После выбора информация
  о поездке сохраняется в базе данных.
* Дополнительно пользователь может просматривать историю своих поездок и оставлять
  заметки о посещённых городах.

## Основные возможности

1. просмотр праздников на ближайшие 7 дней;
2. ввод текущего города пользователя;
3. поиск ближайших городов;
4. выбор города для поездки;
5. сохранение поездки в базу данных;
6. просмотр истории поездок;
7. просмотр информации о конкретной поездке;
8. добавление заметки к поездке.

## Технологические требования

| Требование | Как реализовано в проекте |
|------------|---------------------------|
| Язык программирования Python | Python 3.10+ (разработка велась на 3.11) |
| `telebot` для взаимодействия с Telegram | `travelhunter/presentation/` — экраны, клавиатуры, обработчики |
| `requests` для HTTP-запросов к внешним API | `travelhunter/infrastructure/api/http_client.py` и клиенты сервисов |
| `psycopg2` для взаимодействия с PostgreSQL | драйвер указан в `DATABASE_URL=postgresql+psycopg2://…` |
| `sqlalchemy` для работы с базой данных через ORM | `travelhunter/infrastructure/db/` — модели 2.0-стиля и репозиторий |
| API-ключ Ninjas не хранится в коде и не публикуется в Git | ключ читается из `NINJAS_API_KEY` (файл `.env` в `.gitignore`) |
| Код в ООП-стиле | классы сервисов, клиентов, репозиториев, экранов; наследование и интерфейсы (ABC) |
| Трёхслойная архитектура | `presentation` → `domain` ← `infrastructure` (см. [05_arhitektura.md](05_arhitektura.md)) |
| Взаимодействие с БД через SQLAlchemy | только через `SqlTripRepository`, сервисы работают с интерфейсом `TripRepository` |
| Обработка ошибок Telegram | декоратор `safe_handler` в `handlers.py`, ошибки шлюза логируются в `gateway.py` |
| Обработка ошибок базы данных | `SQLAlchemyError` → `DatabaseError` → понятное сообщение пользователю |
| Обработка ошибок внешних сервисов | `ExternalServiceError` и его наследники, дружелюбные сообщения |
| Ошибка не приводит к аварийному завершению бота | все исключения перехватываются; бот продолжает принимать апдейты |

## Безопасность секретов

* `.env` добавлен в `.gitignore` — в репозиторий попадает только `.env.example`;
* ключи читаются в одном месте — `travelhunter/config.py` (класс `Settings`);
* в исходном коде нет ни одного ключа: `grep -r "api_key =" travelhunter/` покажет
  только чтение из настроек;
* строка подключения к базе логируется без пароля (`Database.safe_url`).
