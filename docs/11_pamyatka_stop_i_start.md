# 11. Памятка: свернуть и развернуть проект (Windows)

Короткая карточка на каждый день: что работает на компьютере, как это
остановить, чтобы не нагружать ПК, и как снова запустить. Ничего из данных при
остановке не теряется.

## Что вообще «крутится», пока вы работаете

| Процесс | Где живёт | Сколько ест |
|---------|-----------|-------------|
| Бот `python run.py` | окно PowerShell, где вы его запустили | ~50–100 МБ ОЗУ |
| Контейнеры `postgres` + `adminer` | Docker (команда `docker compose up -d`) | ~100–300 МБ ОЗУ |
| Docker Desktop + WSL 2 | системный трей (значок кита) | **~1–2 ГБ ОЗУ** — главный потребитель |
| Служба PostgreSQL (только если ставили установщиком, а не Docker) | служба Windows `postgresql-x64-16` | ~50 МБ ОЗУ |

## Свернуть (заканчиваете работу)

1. **Бот:** в его окне PowerShell нажмите `Ctrl+C` (или просто закройте окно).
2. **Контейнеры:** в папке проекта выполните

   ```powershell
   cd C:\Users\User\Downloads\GemInfo-arena-01a0bfe2-geminfo
   docker compose down
   ```

   База данных при этом **не удаляется** — она лежит в volume
   `gamehunter_pgdata` и дождётся вас.
3. **Docker Desktop:** правый клик по значку кита в трее → **Quit Docker
   Desktop**. Это освобождает те самые 1–2 ГБ ОЗУ. То же делает команда

   ```powershell
   wsl --shutdown
   ```

   (после неё Docker Desktop сам показывает, что остановлен).

Готово: ПК снова «пустой». Вкладки браузера с Adminer можно просто закрыть.

## Развернуть (садитесь за проект)

1. Запустите **Docker Desktop** и дождитесь, пока кит в трее станет спокойным
   (надпись «Engine running»).
2. Поднимите базу и проверьте её:

   ```powershell
   cd C:\Users\User\Downloads\GemInfo-arena-01a0bfe2-geminfo
   docker compose up -d
   docker compose ps          # статус Up / running — всё хорошо
   ```

3. Запустите бота:

   ```powershell
   python run.py
   ```

   Не забудьте про VPN или `PROXY_URL` в `.env`, если `api.telegram.org`
   недоступен напрямую.

## Если PostgreSQL установлен службой (вариант Б, без Docker)

| Действие | Команда (PowerShell от администратора) |
|----------|----------------------------------------|
| Остановить базу | `Stop-Service postgresql-x64-16` |
| Запустить базу | `Start-Service postgresql-x64-16` |
| Не запускать службу вместе с Windows | `Set-Service postgresql-x64-16 -StartupType Manual` |
| Вернуть автозапуск | `Set-Service postgresql-x64-16 -StartupType Automatic` |

То же мышкой: `Win+R` → `services.msc` → «postgresql-x64-16» →
«Остановить» / «Запустить».

## Шпаргалка команд

| Команда | Что делает | Данные |
|---------|------------|--------|
| `Ctrl+C` в окне бота | останавливает бота корректно | не трогает |
| `docker compose down` | останавливает и удаляет контейнеры | **сохраняет** базу |
| `docker compose down -v` | то же + удаляет volume | **СТИРАЕТ всю базу!** |
| `docker compose up -d` | поднимает базу и Adminer заново | создаёт контейнеры из volume |
| `docker compose ps` | показать, что запущено | — |
| `docker compose logs -f postgres` | лог базы (`Ctrl+C` — выйти) | — |
| `wsl --shutdown` | полностью освободить память Docker/WSL | не трогает |
| `Stop-Service postgresql-x64-16` | остановить «установленную» PostgreSQL | не трогает |

## Частые вопросы

* **«Я просто закрыл крышку ноутбука — всё сломается?»** Нет: бот и контейнеры
  продолжат работать и есть батарею/память. Перед сном лучше выполнить шаги
  «Свернуть».
* **«После `docker compose down` пропали мои анкеты и отзывы?»** Нет, они в
  volume. Пропасть они могут только после `docker compose down -v`.
* **«Docker Desktop не запускается после `wsl --shutdown`»** Подождите 10–20
  секунд и запустите его снова; если не помогло — перезагрузите Windows.
* **«Бот пишет `[ОШИБКА БАЗЫ ДАННЫХ]`»** Значит, контейнеры не подняты:
  `docker compose up -d`, затем повторите `python run.py`.
